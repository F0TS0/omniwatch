# Current state

OmniWatch is one continuous experience: a compact real browser-signal dossier at `/`, an enforcement-policy configuration at `/enforcement`, and the Martin Luther, 1517 deterministic historical simulation at `/case/luther-1517`. The visitor's own dossier ID, observed signal count, and chosen intervention threshold carry through into the historical simulation via `sessionStorage`, so the two halves read as one system rather than two disconnected demos.

Philadelphia and Estonia 1988 remain deliberately marked as pending manual curation and are not selectable in the primary flow. `/cases` (a plain case archive) and `/present` (a static, explicitly anonymous illustrative present-day timeline) remain as secondary routes, not part of the primary flow, and are unchanged from earlier iterations.

Built-in event choices use a deterministic local index (`lib/classification.ts`) explicitly labelled as not a prediction of intent. A custom event uses the disclosed `POST /api/classify-event` route: only the event text and six generic signal-category names go to Groq, where strict structured relevance assessment occurs; `lib/custom-event.ts` calculates the resulting Enforcement Index locally with fixed weights. Raw browser values remain local, and an unavailable provider shows an explicit unavailable state rather than a generic custom score. The historical intervention threshold is visitor-configurable (50–90%, default 70%) via `lib/simulation.ts`'s `withThreshold`, which derives an effective case without mutating the canonical Luther data; the underlying curated confidence sequence (8, 22, 45, 71, 89, 94) is never recalculated.

Verification on 2026-09-14: `npm test` passed 13 tests; `npx tsc --noEmit`, `npm run build`, and `npm run lint` passed. The full visitor journey (dossier → training → transition → enforcement configuration → Luther simulation → intervention → outcome → final reveal) was driven end-to-end in a headless browser with no console errors.
